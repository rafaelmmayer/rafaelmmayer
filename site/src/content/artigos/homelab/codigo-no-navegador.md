## Ideia do artigo

Este texto pode explicar por que faz sentido ter ambiente de código acessível pelo navegador, mesmo quando ainda existe uma máquina principal de trabalho.

A graça não é substituir um editor local em todos os casos. É ter um lugar sempre perto do servidor, dos arquivos e das ferramentas que rodam ali.

## Pontos para desenvolver

- Diferença prática entre T3 Code e code-server no uso diário.
- Quando abrir projeto inteiro e quando só editar uma configuração.
- Vantagem de estar perto dos serviços do homelab.
- Riscos de expor editor na internet.
- Autenticação e acesso local como regra conservadora.

## Possível estrutura

1. O incômodo de depender da máquina certa.
2. Um editor perto da infra.
3. Dois usos diferentes: programar e administrar arquivo.
4. O que eu não exponho sem cuidado.
5. Como isso conversa com GitHub CLI e agentes.

## Notas soltas

Talvez fechar com uma ideia simples: o navegador vira uma bancada. Não precisa ser o melhor editor do mundo para ser útil.
